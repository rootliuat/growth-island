# 成长岛产品需求文档

版本：v0.1
日期：2026-05-28
适用范围：前端重构、左侧菜单设计、模块页面设计、MVP 开发排序

## 1. 产品概述

### 1.1 产品命名

- 对外产品名：成长岛
- 系统侧栏品牌：成长小精灵 Classroom Elf
- 首页主场景名：北海成长岛

“成长岛”是系统产品名称；“北海成长岛”是首页主视觉和主工作台，不等同于整个系统。

### 1.2 产品定位

成长岛是一套面向幼儿园班级的游戏化德育成长系统。它把传统积分、行为记录、评比和班级活动，转化为可在电子白板、大屏或班级电脑上运行的精灵家园地图。

每个孩子拥有一只独立精灵。孩子通过日常表现、语音表达、数学 PK、老师评价、班级活动等方式获得 XP。XP 推动精灵从蛋逐步孵化、升级、变化形态，并让孩子在地图上看见自己的成长。

产品不是后台积分表，而是一个持续运营的班级成长游戏世界。

### 1.3 产品价值

孩子看到的是：

- 我的精灵长大了
- 我的家变漂亮了
- 我今天的好行为有记录
- 我可以通过努力升级

老师得到的是：

- 班级德育记录更轻松
- 行为分类更标准
- 成长数据可追踪
- 复核、撤销和调整都有依据

园所和评审看到的是：

- 德育项目有可展示的产品形态
- 班级日常行为有结构化数据
- 孩子的成长过程可以被直观看见

## 2. 使用场景与用户角色

### 2.1 使用场景

系统主要运行在班级电子白板、大屏或班级电脑上。老师登录一个班级账号，孩子不需要个人账号。全班孩子共同生活在同一个成长岛里。

孩子可以在老师组织下点击自己的精灵，查看等级、XP、最近表现，也可以通过语音或文字描述“今天做了什么”。系统识别后给出德育分类和建议 XP，老师确认后写入成长记录。

第一阶段重点服务班级内使用，不做复杂账号体系。

### 2.2 老师

老师是主要操作者。

老师需要完成：

- 查看全班成长岛
- 选择孩子和精灵
- 手动加分、扣分、撤销记录
- 记录孩子表现
- 复核 AI 判断
- 组织数学 PK
- 组织随机点名
- 组织积分抽奖
- 管理积分商店
- 查看成长记录和数据
- 维护基础设置

老师界面可以包含管理能力，但不应呈现为传统后台表格。管理操作应包装在游戏化 HUD、模块页面或产品化工作台中。

### 2.3 孩子

孩子不是登录用户，不需要个人账号。

孩子主要参与：

- 查看自己的精灵和家园
- 看到 XP 增长和升级反馈
- 参与数学 PK
- 参与随机点名
- 参与积分抽奖
- 参与积分兑换
- 通过语音描述自己的表现

孩子视角应弱化复杂管理功能，不强调扣分和排名压力。

### 2.4 园所 / 展示观看者

园所、评审或家长展示场景主要关注：

- 成长岛地图
- 班级精灵家园
- 七大德育维度
- 成长记录沉淀
- 活动玩法
- 数据展示能力

## 3. 产品主线

产品的数据和体验主线为：

孩子 → 专属精灵 → 专属家园 → 成长行为 → XP 变化 → 等级变化 → 精灵形态变化 → 成长记录沉淀 → 德育画像与班级活动

系统设计不应只围绕“分数”展开，而应围绕“精灵成长”和“班级世界”展开。

## 4. 核心系统

### 4.1 精灵成长系统

每个孩子拥有一只独立精灵。即使两个孩子选择同一种精灵，它们也是不同 ID，拥有各自的名字、XP、等级、形态、家园和成长记录。

精灵成长分为蛋期和精灵期：

- 初始为精灵蛋
- 获得 XP 后蛋逐步裂开、发光、露出局部、探头
- 孵化后进入 Lv.2 幼态精灵
- Lv.3 至 Lv.8 逐步增加光效、饰品、纹样、装备和守护者感

验收标准：

- 每个孩子都能绑定独立精灵
- 精灵有姓名、等级、XP、形态和家园
- XP 变化后，精灵状态和成长记录同步变化
- 即使精灵物种相同，不同孩子的数据也互不影响

### 4.2 XP 与等级

XP 是成长能量，用于推动精灵升级和形态变化。

加分来源包括：

- 老师手动评价
- 语音记录识别
- AI 德育判断
- 数学魔法 PK 获胜
- 班级活动奖励
- 后续抽奖或任务奖励

扣分来源包括：

- 老师手动扣分
- 复核后的负向记录
- 后续规则配置

规则要求：

- XP 不低于 0
- 升级和降级都影响精灵形态
- 加分反馈应使用 XP 光点、成长树、精灵反馈等游戏化表现
- 扣分反馈应克制，不做强烈惩罚动画

验收标准：

- 手动加分、扣分会正确更新 XP
- XP 不会低于 0
- XP 变化会生成成长记录
- 首页地图、右侧 HUD、底部精灵队伍同步更新

### 4.3 七大德育维度

系统将成长行为归类到七大方向：

- 家国情怀
- 意志坚韧
- 积极阳光
- 勇毅有力
- 激浊扬清
- 开拓创新
- 尊矩守法

七大维度用于：

- AI 分类
- 老师复核
- 成长记录筛选
- 孩子成长画像
- 班级德育数据展示

验收标准：

- 成长记录必须能关联德育维度
- 语音或文本识别结果必须给出分类建议
- 老师可以确认、调整或驳回建议
- 数据管理模块可按维度展示或筛选记录

### 4.4 成长岛地图

首页是一张 2D / 2.5D 游戏地图，而不是后台页面。

地图需要承载：

- 成长树
- 精灵社区
- 道路和装饰物
- 每个孩子的精灵小屋
- 精灵角色
- 功能区域入口

地图区域职责：

- 成长树广场：XP 汇聚、升级反馈
- 精灵社区：孩子精灵居住区
- 数学竞技场：数学魔法 PK 入口
- 活动区：德育任务、班级活动入口
- 排行区：周榜、月榜、总榜展示

验收标准：

- 每个精灵都有自己的家，不是随机头像点位
- 点击精灵或小屋能选中孩子并聚焦到家门口
- 地图能支撑首页工作台操作
- 地图视觉应传达“班级成长游戏世界”，不能像后台仪表盘

## 5. 当前首页已有能力与后续模块关系

当前首页已经具备或正在承载的能力：

- 北海成长岛地图
- 全班精灵和家园展示
- 当前精灵选中
- 右侧 HUD
- 底部精灵队伍
- 手动加分

- 撤销记录
- 对话 / 成长记录入口

- XP 与等级同步

后续需要扩展为独立模块的能力：

- 随机点名
- 语音记录
- 数学竞技场独立页面
- 积分抽奖
- 积分商店
- 排行榜

- 系统设置

原则：第一阶段不拆掉首页已有业务能力。左侧菜单先提供系统级信息架构，非首页模块以产品化占位页承接，后续再逐步实现完整功能。

## 6. 全局菜单结构

左侧菜单是系统级导航，不属于首页地图内部。

建议菜单：

1. 首页
2. 随机点名
3. 语音记录
4. 数学竞技场
5. 积分抽奖
6. 积分商店
7. 排行榜
8. 数据管理
9. 系统设置

视觉要求：

- 品牌名称为“成长小精灵 Classroom Elf”
- 显示当前班级
- 深绿色 / 青绿色产品感
- active 状态清晰
- 不过度低幼
- 适配 1366、1440、1920 大屏
- 窄屏可收起为图标栏

布局要求：

- 左侧为全局导航
- 右侧为当前模块工作区
- 默认进入首页，显示北海成长岛
- 切换其他菜单时显示对应模块页面或占位页
- 返回首页时继续显示成长岛

## 7. 模块需求

### 7.1 首页：北海成长岛

用途：系统主视觉、主工作台和班级成长世界入口。

页面内容：

- 顶部工具栏：当前页面名、班级信息、幼儿数量、家园数量、同步状态、老师模式、展示模式
- 地图区域：成长岛地图、精灵家园、功能区域、当前焦点、地图互动
- 右侧 HUD：当前伙伴、等级、XP、形态、成长记录、待复核、入住信息、老师工具
- 底部精灵队伍：搜索、区域筛选、精灵头像、孩子姓名、等级、选中状态

主要操作：

- 点击底部精灵或地图小屋选择孩子
- 地图聚焦到孩子家园
- 手动加分、扣分、撤销记录
- 进入对话 / 语音记录
- 进入数学 PK
- 查看最近成长记录

当前已有能力：

- 地图、HUD、Dock 已具备基础可用性
- 加分、扣分、撤销、成长记录、数学 PK 已存在

MVP 第一阶段要做：

- 嵌入左侧产品壳
- 保持地图可用
- 保持右侧 HUD 可用
- 保持底部精灵队伍可用
- 保持加分、扣分、撤销、对话记录、数学 PK 可用
- 顶部工具栏适配产品壳

MVP 第一阶段暂不做：

- 不大改地图布局
- 不重构 PixiJS
- 不新增复杂地图区域功能
- 不新增后端接口

验收标准：

- 首页在产品壳内正常显示
- 原有地图、HUD、Dock 不被破坏
- 加分、扣分、撤销、数学 PK 仍可用
- 首页第一眼仍是成长游戏地图，而不是后台仪表盘

### 7.2 随机点名

用途：课堂活动中快速抽取孩子，并与成长岛精灵联动。

页面内容：

- 当前点名池人数
- 已点名人数
- 未点名人数
- 当前抽中孩子
- 精灵头像
- 孩子等级
- 家园编号
- 开始点名按钮
- 重置点名池按钮
- 已点名列表
- 聚焦成长岛按钮

主要操作：

- 从当前班级孩子中随机抽取 1 人
- 可选择是否排除已点名孩子
- 重置点名池
- 抽中后切回首页并聚焦到对应精灵家园

MVP 第一阶段要做：

- 产品化占位页
- 展示模块说明、功能卡片、主要按钮、次要按钮
- 说明与成长岛首页的联动

后续模块实现要做：

- 本地随机抽取
- 本地记录已点名列表
- 排除已点名孩子
- 聚焦成长岛

MVP 第一阶段暂不做：

- 不做后端保存
- 不做复杂点名权重
- 不做多班级点名
- 不做点名历史分析

验收标准：

- 页面清楚说明点名用途
- 有“开始点名”和“重置点名池”
- 功能卡片说明点名池、已点名、成长岛联动
- 后续支持列表完整

### 7.3 语音记录

用途：让孩子或老师描述成长行为，由系统转写、分类并给出建议 XP。

页面内容：

- 孩子选择器
- 语音按钮
- 文本输入框
- 常用记录模板
- 提交分析按钮
- AI 判断结果
- 建议分类
- 建议 XP
- 判断理由
- 待复核队列
- 最近语音记录

主要操作：

- 选择孩子
- 输入文本或发起语音
- 提交分析
- 查看分类和 XP 建议
- 老师确认、调整或驳回
- 通过后生成成长记录并同步首页

MVP 第一阶段要做：

- 产品化占位页
- 明确第一阶段可先使用文本输入 + 语音按钮占位
- 展示 AI 判断、复核、成长岛同步的流程

后续模块实现要做：

- 选择孩子
- 输入文本
- 复用现有 AI 或本地规则判断
- 显示建议结果
- 老师确认或驳回
- 通过后生成成长记录
- 返回首页聚焦孩子

MVP 第一阶段暂不做：

- 不做真实浏览器录音
- 不做语音上传
- 不做长期音频管理
- 不做复杂 AI 配置

验收标准：

- 页面能解释语音记录到成长记录的闭环
- 有文本输入、语音占位、分析按钮的界面规划
- 明确老师复核是必经动作
- 明确通过后同步首页 XP 与记录

### 7.4 数学竞技场

用途：两个孩子进行 1v1 数学魔法 PK，并把胜利结果转化为成长 XP。

基础规则：

- 双方 HP 100
- 题目为 20 以内加减法
- 答对一次造成 20 伤害
- 答错不能攻击
- 对方 HP 归零后获胜
- 胜者 +30 XP
- 败者不扣 XP

页面内容：

- 参赛孩子 A
- 参赛孩子 B
- 双方精灵头像
- HP 条
- 当前题目
- 答案选项
- 战斗日志
- 胜负结果
- 返回成长岛按钮

主要操作：

- 选择两个孩子
- 开始 PK
- 回答题目
- 结算胜负
- 胜者获得 XP
- 返回首页并同步记录

当前已有能力：

- 首页中已有数学 PK 能力

MVP 第一阶段要做：

- 保留当前数学 PK 功能
- 左侧菜单中提供数学竞技场入口或产品化占位页
- 明确它是核心玩法，不从产品信息架构中删除

MVP 第一阶段暂不做：

- 不做复杂题库
- 不做多人竞技
- 不做赛季系统
- 不做 PK 排名

验收标准：

- 页面清楚展示 PK 规则
- 能从菜单理解数学竞技场是核心模块
- 当前首页数学 PK 不被破坏
- 后续实现时胜者 XP 和成长记录必须同步首页

### 7.5 积分抽奖

用途：把成长激励转化为班级抽奖体验。

产品原则：第一阶段建议做展示型抽奖，不消耗 XP，避免影响成长等级。后续可拆分“成长 XP”和“可消费积分”。

页面内容：

- 当前参与孩子
- 当前 XP / 等级
- 奖池
- 抽奖按钮
- 中奖结果
- 抽奖记录
- 查看精灵按钮

主要操作：

- 选择孩子
- 查看奖池
- 发起抽奖
- 展示中奖结果
- 返回首页聚焦孩子

MVP 第一阶段要做：

- 产品化占位页
- 展示奖池、抽奖记录、成长岛联动的规划
- 明确第一阶段不扣 XP

后续模块实现要做：

- 静态奖池
- 本地随机抽奖
- 本地记录本次抽奖
- 不影响 XP

MVP 第一阶段暂不做：

- 不做真实库存
- 不做概率后台配置
- 不做积分扣减
- 不做后端保存

验收标准：

- 页面清楚说明抽奖不会影响成长 XP
- 有“开始抽奖”和“查看成长岛”操作规划
- 有奖池、结果、记录三个功能区

### 7.6 积分商店

用途：班级奖励兑换台，用于把积分激励落地成奖励体验。

页面内容：

- 当前孩子
- 当前 XP
- 奖品分类
- 奖品卡片
- 所需积分
- 库存
- 兑换按钮
- 兑换记录

主要操作：

- 选择孩子
- 查看奖品
- 判断 XP 是否足够
- 生成兑换记录
- 返回首页查看精灵

MVP 第一阶段要做：

- 产品化占位页
- 展示奖品卡、兑换记录、成长岛联动
- 明确第一阶段不扣 XP、不做真实库存

后续模块实现要做：

- 静态奖品列表
- 选择孩子
- 判断 XP 是否足够
- 本地生成兑换记录

MVP 第一阶段暂不做：

- 不做支付
- 不做复杂库存
- 不做奖品上传
- 不做兑换审批
- 不做 XP 扣减

验收标准：

- 页面清楚说明积分商店是班级奖励兑换台
- 奖品卡片、兑换按钮、兑换记录结构明确
- 不影响首页 XP 规则

### 7.7 排行榜

用途：展示孩子成长状态，并用游戏化方式表达班级成长成果。

排行榜类型：

- 周榜
- 月榜
- 总榜

视觉方向：

- 领奖台
- 卷轴
- 贝壳榜单
- 精灵展示卡

页面内容：

- 榜单类型切换
- 前三名展示
- 当前孩子位置
- 全班列表
- XP
- 等级
- 精灵头像
- 时间范围

主要操作：

- 切换榜单类型
- 查看前三名
- 查找某个孩子
- 返回首页聚焦孩子

MVP 第一阶段要做：

- 产品化占位页
- 展示排行榜视觉结构和功能卡片
- 首页可保留当前排名信息

后续模块实现要做：

- 根据当前 XP 生成总榜
- 静态周榜 / 月榜占位
- 展示前三名和全班列表

MVP 第一阶段暂不做：

- 不做真实周月统计
- 不做赛季系统
- 不做复杂称号
- 不强化排名压力

验收标准：

- 页面体现游戏化榜单，不像后台表格
- 总榜规则明确为按 XP 排序
- 周榜和月榜明确为后续统计能力

### 7.8 数据管理

用途：查看和维护成长记录，是老师的数据工作台。

页面内容：

- 幼儿名单
- 成长流水
- 复核记录
- 搜索
- 筛选
- 导出按钮占位

- 导出按钮先占位

后续模块实现要做：

- 展示当前孩子列表
- 展示成长记录
- 展示待复核记录
- 支持搜索孩子
- 支持查看同步状态

MVP 第一阶段暂不做：

- 不做批量导入
- 不做复杂编辑
- 不做权限系统

## 8. 模块联动关系

### 8.1 首页作为中心

首页是所有模块的视觉中心和状态中心。其他模块产生的结果，应尽量能回到首页并作用于孩子、精灵、XP 或成长记录。

### 8.2 联动规则

| 来源模块 | 联动到首页 | 数据影响 |
| --- | --- | --- |
| 随机点名 | 抽中后可聚焦孩子家园 | 第一阶段不新增 XP |
| 语音记录 | 确认后同步 XP 和成长记录 | 生成德育记录 |
| 数学竞技场 | PK 后返回首页聚焦胜者 | 胜者 +30 XP |
| 积分抽奖 | 抽奖后可查看孩子精灵 | 第一阶段不扣 XP |
| 积分商店 | 兑换后可查看孩子精灵 | 第一阶段不扣 XP |
| 排行榜 | 点击孩子可回首页聚焦 | 读取 XP 排序 |
| 数据管理 | 点击孩子或记录可回首页聚焦 | 读取成长记录 |
| 系统设置 | 影响显示和规则说明 | 第一阶段不真实保存 |

### 8.3 统一交互要求

- 所有模块都应提供“返回成长岛”或“聚焦成长岛”能力
- 选择孩子后，应尽量能与首页当前选中孩子联动
- 任何会改变 XP 的操作都必须生成成长记录
- 任何 AI 判断都必须经过老师确认或可复核
- 第一阶段非首页模块不应破坏首页现有状态

## 9. 第一阶段 MVP 范围

### 9.1 第一阶段目标

第一阶段目标是搭建产品信息架构和左侧菜单壳，让当前首页从单页应用升级为“成长岛系统”的首页模块，同时保持现有业务功能可用。

### 9.2 第一阶段要做

1. 完成产品需求文档
2. 新增左侧产品菜单
3. 首页嵌入产品壳
4. 保持首页原有地图、HUD、Dock、对话记录、数学 PK 可用
5. 非首页模块先做产品化占位页
6. 占位页包含模块说明、功能卡片、主要按钮、次要按钮、后续支持列表
7. 保证大屏显示稳定，不出现横向滚动
8. 不破坏现有业务逻辑

### 9.3 第一阶段不做

- 不新增真实路由
- 不新增后端接口
- 不新增复杂账号权限
- 不做真实语音录音
- 不做真实抽奖库存
- 不做真实积分兑换扣减
- 不做真实数据导出
- 不重构 PixiJS 地图
- 不改变现有 XP 计算逻辑
- 不改变现有数学 PK 规则
- 不改变现有 AI 复核逻辑

### 9.4 第一阶段优先级

P0：

- 左侧产品壳
- 首页嵌入产品壳
- 保持首页业务可用
- 非首页模块占位页标准组件

P1：

- 随机点名占位页
- 语音记录占位页
- 数学竞技场占位页
- 排行榜占位页

P2：

- 积分抽奖占位页
- 积分商店占位页
- 数据管理占位页
- 系统设置占位页

## 10. 非首页模块占位页标准

每个非首页模块占位页必须包含：

- 模块标题
- 模块说明
- 3 个功能卡片
- 1 个主要按钮
- 1 个次要按钮
- 后续将支持列表
- 与成长岛首页的联动说明

占位页禁止只写“开发中”。占位页应让老师、园所或评审理解该模块未来要做什么，以及它如何和成长岛首页连接。

示例：随机点名占位页

- 标题：随机点名
- 说明：从当前班级中随机抽取孩子，并可同步聚焦成长岛精灵。
- 功能卡片 1：点名池，当前班级所有孩子
- 功能卡片 2：今日已点，记录本轮点名情况
- 功能卡片 3：成长岛联动，抽中后可聚焦对应精灵家园
- 主要按钮：开始点名
- 次要按钮：重置点名池
- 后续将支持：按区域筛选、排除已点名、点名后记录成长行为、点名结果同步到成长岛

## 11. UI 与前端设计指导

### 11.1 整体方向

成长岛的界面应呈现为“游戏化班级成长产品”，不是后台系统。

要求：

- 首页优先呈现地图和精灵家园
- 业务工具包装为游戏 HUD 或产品化模块
- 左侧菜单清晰但不抢地图主视觉
- 非首页页面应像教育游戏产品的功能页，不像普通管理后台
- 大屏和电子白板优先

### 11.2 视觉边界

可以使用：

- 深绿色 / 青绿色产品侧栏
- 柔和卡片
- 游戏化按钮
- 精灵头像
- 奖励、榜单、记录等视觉符号

避免使用：

- 传统后台表格堆叠
- 大面积冷色管理台风格
- 过多表单输入
- “开发中”空页面
- 孩子视角中过强的排名和扣分压力

## 12. 产品验收标准

产品文档和第一阶段前端完成后，应能回答：

1. 成长岛是什么产品
2. 为什么它不是积分后台
3. 老师怎么用
4. 孩子看到什么
5. 首页为什么是地图
6. 精灵成长系统怎么运作
7. XP 从哪里来
8. 七大德育维度怎么用
9. 语音和 AI 判断如何进入成长记录
10. 数学 PK 如何影响 XP
11. 左侧菜单有哪些模块
12. 每个模块第一阶段做什么
13. 每个模块暂不做什么
14. 首页和其他模块如何联动
15. 第一阶段前端应该优先实现什么

## 13. 后续开发顺序建议

1. 产品壳与左侧菜单
2. 首页接入产品壳并保持现有业务稳定
3. 非首页模块占位页通用模板
4. 随机点名模块
5. 语音记录模块的文本输入与复核闭环
6. 数学竞技场独立页面
7. 排行榜总榜
8. 积分抽奖与积分商店展示版
9. 数据管理工作台
10. 系统设置静态配置页

开发顺序应优先保证“老师打开系统后知道这是一个完整产品”，再逐步补齐真实功能。
