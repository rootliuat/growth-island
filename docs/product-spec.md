# 北海成长岛产品规格

版本：v0.2
日期：2026-06-04
适用范围：当前 P0-P2 产品化收口，电子白板课堂使用

## 1. 当前范围

北海成长岛当前只服务班级现场的两类用户：

- 幼儿园孩子：来到电子白板前，直接点自己的精灵，说出今天的成长，看到精灵获得能量。
- 主班或配班老师：组织排队，辅助孩子操作，确认、修改、稍后处理或补记成长记录。

当前阶段不做多角色后台，不做跨班级运营工作台，不做正式报表体系，不做复杂权限系统。所有页面和文案都应优先服务“孩子在岛上完成一次成长表达”。

## 2. 产品定位

北海成长岛是一套部署在班级电子白板上的德育成长游戏 HUD。

它不是老师积分表，也不是后台管理系统。它的核心闭环是：

```text
点自己的精灵 -> 说成长 -> 老师轻量确认 -> 能量进精灵 -> 回到全岛 -> 下一位孩子自选
```

成功状态：

- 孩子能在全岛上找到自己的精灵或通过底部队伍快速选中自己。
- 说成长、识别、确认、能量反馈都发生在海岛主画面里。
- 老师工具靠边、收起、低干扰，不抢孩子主流程。
- XP、等级、德育维度和成长记录沉淀在系统里，但儿童端不暴露后台结构。

## 3. 核心原则

1. 幼儿是主角：地图、精灵、麦克风和能量反馈优先，文字说明尽量少。
2. 老师是守门员：确认和补记可靠，但默认靠边，不成为首页主操作台。
3. 海岛承载流程：不要把体验拆成选择页、录音页、结果页。
4. 能量替代分数表：儿童端看见光点、能量、精灵反应和区域点亮。
5. 课堂可用：大屏清楚、触控友好、低误触、低噪声。

## 4. 主流程

### 4.1 全岛等待

默认画面显示成长岛地图、孩子精灵、成长树、底部精灵队伍和轻量老师入口。

常驻信息只保留必要状态，例如当前孩子、待老师看数量、同步状态。不要在首页放大标题、长引导语或成人化说明。

### 4.2 点选精灵

孩子可以直接点地图上的精灵，也可以点底部队伍中的自己。

点选后应：

- 镜头聚焦到当前精灵和小屋。
- 当前精灵、名字和等级清楚可见。
- 其他控制弱化，麦克风入口成为主动作。
- 底部队伍保持可展开，便于老师辅助或下一位孩子自己选择精灵。

### 4.3 说成长

孩子点麦克风后进入说成长状态。

状态表达优先使用：

- 麦克风图标。
- 声波动画。
- 小贝壳、星星或光点。
- 精灵附近的短气泡。

儿童端不显示长说明、识别详情、置信度或后台判断过程。

### 4.4 老师确认

系统识别后，老师角落卡出现建议结果。

老师卡片默认紧凑，至少包含：

- 当前孩子。
- 儿童可懂能量词。
- 建议 XP。
- 通过、修改、稍后处理。

展开后可以显示识别文本、专业德育维度、判断理由和置信度。完整信息只给老师看。

### 4.5 能量到账

老师通过后，儿童端看到能量反馈：

- 精灵附近出现短气泡，例如“友爱 +20”。
- 能量光点进入精灵或飞向成长树。
- 对应德育区域轻微点亮。
- 成长记录写入流水。
- 完成后镜头回到全岛，下一位孩子自己选择精灵继续。

## 5. 德育能量表达

系统内部仍使用七大德育维度：

- 家国情怀
- 意志坚韧
- 积极阳光
- 勇毅有力
- 激浊扬清
- 开拓创新
- 尊矩守法

儿童端使用更短的能量词：

| 专业维度 | 儿童端表达 | 视觉方向 |
| --- | --- | --- |
| 家国情怀 | 爱家乡能量 | 小旗、老街、海浪 |
| 意志坚韧 | 坚持能量 | 小树苗、山路 |
| 积极阳光 | 友爱能量 | 太阳、爱心、暖光 |
| 勇毅有力 | 勇气能量 | 灯塔、小旗 |
| 激浊扬清 | 整洁能量 | 贝壳、水滴 |
| 开拓创新 | 创想能量 | 星星、光点 |
| 尊矩守法 | 规则能量 | 盾牌、路标 |

## 6. 当前模块定位

首页是孩子主流程中心。其他模块只能作为课堂辅助或老师兜底。

| 模块 | 当前定位 | 当前要求 |
| --- | --- | --- |
| 地图 | 主体验 | 第一视觉，支持点选、聚焦、能量反馈 |
| 精灵队伍 | 找孩子 | 收起态显示当前孩子，展开态快速选全班 |
| 说成长 | 主动作 | 全岛内完成，不跳到独立流程页 |
| 老师补记 | 兜底 | 靠边、低干扰，服务老师快速补录 |
| 抽取台 | 课堂活动 | 抽中孩子后能回岛定位，不加重主屏 |
| 小屋 | 成长档案 | 看当前孩子精灵、等级和记录 |
| 闯关 | 辅助活动 | 弱化打斗感，表现为魔法光点和挑战 |
| 抽奖、小铺、荣誉 | 扩展激励 | 不抢首页主流程，不制造排名压力 |
| 账本、设置 | 老师工具 | 收在老师工具里，避免进入孩子主视觉 |

## 7. 白板触控要求

当前 P2 的触控目标是让大屏使用稳定：

- 地图可拖动、缩放、点选，不误触底部 dock。
- 关键触控目标尽量不小于 44px。
- 底部队伍收起态能看清当前孩子名字和“说成长”状态。
- 底部队伍展开态能搜索、筛选、选择全班孩子，不遮挡关键老师确认卡。
- 模块页在 390px 窄屏和 1440px 桌面都不能出现横向溢出。
- 触控反馈要清楚，不依赖 hover。

## 8. 图片和资产要求

当前阶段需要资产服务主流程，不为装饰而加图。

优先资产：

- 麦克风待说状态。
- 声波和识别中状态。
- 能量光点、能量轨迹、成功气泡。
- 选中精灵光圈、全班自选入口提示。
- 德育区域点亮效果。

资产生产使用项目现有流程。精灵和地图资产必须保持北海成长岛风格，最终运行图要有可验证的透明通道或已转 WebP runtime 版本。需要抠图时使用项目记录的本地模型流程。

## 9. 当前不做

以下能力不进入当前 P0-P2：

- 多班级或多机构后台。
- 多身份账号体系。
- 正式报表和外发材料。
- 复杂任务流转。
- 商城库存、支付和真实消费体系。
- 复杂题库、赛季、多人对战。
- 大规模数据维护工具。

这些能力不能反向影响当前首页、孩子流程和老师轻量确认的设计优先级。

## 10. P0-P2 验收

P0 范围收口：

- `PRODUCT.md` 和本文档只以孩子和老师为当前核心用户。
- 文档不再把当前阶段描述为后台或菜单壳工程。
- 当前不做内容不进入主流程和前端优先级。

P1 孩子主流程：

- 孩子能从地图或底部队伍选择自己。
- 说成长状态在海岛内完成。
- 老师确认卡不遮挡主视觉。
- 通过后有明确能量到账反馈。
- 完成后能回到全岛，等待下一位孩子自选精灵。

P2 白板触控：

- 桌面、白板和窄屏无横向溢出。
- 触控目标满足课堂使用。
- 底部队伍、地图缩放、回岛定位、老师确认都能稳定操作。
- 关键状态不靠小字或 hover 才能理解。
