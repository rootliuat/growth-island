# 幼儿自助德育成长岛交互方案

记录日期：2026-05-31

## 1. 核心定位

北海成长岛的核心不是老师后台、学科闯关或传统积分表，而是部署在幼儿园电子白板上的幼儿自助德育成长体验。

核心场景：

1. 老师组织小朋友排队。
2. 小朋友一个个来到电子白板前。
3. 小朋友直接在海岛上点自己的精灵。
4. 镜头聚焦到该精灵和家园。
5. 小朋友对着精灵说出今天做了什么。
6. 系统语音识别并提取行为内容。
7. 模型判断行为对应的德育维度和成长能量。
8. 老师轻量把关，通过、修改或稍后复核。
9. 精灵获得成长能量，成长树和对应海岛区域产生反馈。
10. 镜头回到全岛，下一位小朋友继续。

一句话定位：

> 让小朋友自己说出今天的成长，让精灵把好行为变成看得见的品格能量；老师在旁边轻量把关。

## 2. 设计原则

### 2.1 幼儿是主角

系统默认体验应面向孩子，而不是面向老师后台。

孩子看到的是：

- 自己的精灵
- 海岛
- 麦克风图标
- 声波和光效
- 精灵获得能量
- 成长树发光

孩子不应看到：

- AI 置信度
- 完整后台判断过程
- 复杂表单
- 复核表格
- 大段说明文字
- 学科任务
- 排名压力

### 2.2 老师是组织者和守门员

老师可以把关，但不应成为整个体验的主操作中心。

老师负责：

- 组织排队
- 辅助孩子点选精灵
- 必要时帮助重录
- 查看识别文本
- 确认、修改或驳回 AI 建议
- 课后处理待复核记录

老师入口应靠边、轻量、默认收起，不抢占海岛主视觉。

### 2.3 海岛是主界面，不是流程页

不要把流程做成：

```text
首页 → 精灵选择页 → 录音页 → 结果页 → 回到选择页
```

推荐做成：

```text
全岛 → 点精灵 → 镜头聚焦 → 说话 → 能量反馈 → 回到全岛
```

孩子应该一直感觉自己在海岛上和精灵互动，而不是在填写系统流程。

### 2.4 主屏尽量无文字

幼儿未必能读懂大量文字，主屏不需要成人化引导句。

不建议常驻显示：

- 找到你的精灵，说说今天的成长吧
- 今天的成长岛
- 精灵们在等你
- 谁来给精灵加能量
- 小精灵想听你说一说
- 今天谁先来

主屏应主要依靠：

- 精灵位置
- 精灵动作
- 麦克风图标
- 声波动画
- 光点飞行
- 成长树发光
- 区域点亮

必要文字只在短暂的精灵气泡或老师确认卡中出现。

## 3. 海岛内主流程

### 3.1 默认全岛状态

画面内容：

- 全岛地图作为第一视觉。
- 每个孩子的精灵在自己的家园附近。
- 中央成长树轻微呼吸发光。
- 德育区域保持安静状态，只有当天有成长记录的区域可有轻微光效。
- 主屏不显示大段引导文案。
- 老师入口、待确认数量等放在角落。

允许的常驻信息：

```text
今日成长 12
待确认 2
```

也可以仅用图标和数字表达，避免文字占画面。

### 3.2 点击精灵

小朋友上来后，直接在海岛上点自己的精灵。

反馈：

- 镜头平滑推进到该精灵家园。
- 被选中的精灵轻微放大、发光。
- 其他 UI 淡出。
- 精灵头顶出现麦克风圆形图标。
- 不显示长文字。

可选短标签：

```text
我
```

但优先不显示文字，只用精灵高亮和麦克风图标表达。

### 3.3 可说话状态

画面表现：

- 麦克风图标轻轻呼吸。
- 精灵转向屏幕外，像在等待孩子说话。
- 家园小灯亮起。
- 成长树保持微弱呼吸。

不显示“请说话”“说给精灵听”等文字。

### 3.4 录音状态

孩子点击或按住麦克风后进入录音。

画面表现：

- 麦克风变成声波动画。
- 声波随音量起伏。
- 精灵认真听，眨眼、点头或耳朵/触角轻动。
- 小星星、小贝壳或光点围绕精灵漂浮。
- 背景可轻微降噪，焦点集中在精灵。

不显示文字。

### 3.5 识别状态

录音结束后进入识别。

画面表现：

- 麦克风变成小贝壳或光球旋转。
- 精灵做思考动作。
- 三个小光点跳动。
- 成长树与精灵之间出现很淡的光线连接。

不显示文字。

### 3.6 识别完成

识别完成后，儿童端只显示非常短的摘要或直接进入能量结果。

建议使用精灵气泡，而不是系统弹窗。

可显示：

```text
帮助同伴
```

或：

```text
整理玩具
```

显示时间：1.5 秒左右。

完整识别文本不在海岛主画面常驻，放到老师确认卡和成长档案中。

### 3.7 老师把关

老师确认卡在角落出现，不遮挡海岛和精灵。

默认紧凑态：

```text
积极阳光 +20
[✓] [改]
```

展开态：

```text
识别：我今天主动帮同学收玩具
建议：积极阳光 +20
置信度：82%
[通过] [修改] [稍后]
```

规则：

- AI 专业判断只给老师看。
- 孩子主画面不显示置信度。
- 负向、低置信度、敏感内容必须老师确认。
- 正向高置信度内容可根据园所设置选择自动通过或老师一键通过。

### 3.8 成功加分反馈

老师通过或系统自动通过后，儿童端显示能量反馈。

推荐显示：

```text
友爱 +20
```

或：

```text
友爱能量
+20
```

动画：

- 精灵跳起或开心旋转。
- 能量光点从精灵飞向中央成长树。
- 对应德育区域轻轻点亮。
- 精灵家园出现小花、贝壳、星星或灯光。
- 成长树发光一次。

显示时间：2 秒左右。

### 3.9 回到全岛

成功反馈结束后：

- 镜头自动拉回全岛。
- 当前孩子精灵可短暂显示完成状态，例如小星星或小勾，不用文字。
- 下一位孩子直接点自己的精灵。

不要回到单独的“精灵选择页”。

## 4. 对话文字显示规范

### 4.1 总体原则

主屏和录音过程尽量无文字。

文字只在三个场景出现：

1. 识别完成后的短摘要。
2. 加分结果。
3. 异常或需要重说。

所有儿童端文字都应短、大、圆润、可自动消失。

### 4.2 精灵气泡

儿童端文字统一使用精灵气泡，不使用系统弹窗。

气泡样式：

- 贝壳白或奶油白底。
- 圆角。
- 有小尾巴指向精灵。
- 轻阴影或描边。
- 字号大。
- 最多 1 到 2 行。
- 不遮挡岛屿主体。
- 跟随精灵位置，靠边时自动避让。

示例：

```text
┌──────────┐
│ 友爱 +20 │
└────▼─────┘
     精灵
```

### 4.3 儿童端可显示内容

优先级从高到低：

1. 图标 + 数字

```text
💛 +20
```

2. 能量短词 + 数字

```text
友爱 +20
```

3. 行为摘要

```text
帮助同伴
```

4. 异常短句

```text
再说一次
```

不显示：

- AI 建议
- 置信度
- 德育维度解释
- 完整长文本
- 复杂原因
- 后台审核状态

### 4.4 老师端文字

老师端可以显示完整信息，但应放在小确认卡中。

老师可见内容：

- 识别文本
- AI 建议维度
- 建议分值
- 置信度
- 风险标记
- 通过、修改、稍后、驳回操作

老师卡片不应超过屏幕宽度的 25%，默认收起或紧凑显示。

## 5. 德育能量儿童化表达

七大德育维度仍是系统和老师侧的专业分类，但儿童端应使用更容易理解的能量词。

| 专业维度 | 儿童端表达 | 场景建议 | 图标建议 | 色彩建议 |
| --- | --- | --- | --- | --- |
| 家国情怀 | 爱家乡能量 / 爱祖国能量 | 家乡老街 / 国旗广场 | 小旗 / 海浪老街 | 金红 |
| 意志坚韧 | 坚持能量 | 坚持小径 | 小树苗 / 山峰 | 草绿 |
| 积极阳光 | 友爱能量 / 阳光能量 | 友爱港湾 | 爱心 / 太阳 | 暖黄 / 珊瑚橙 |
| 勇毅有力 | 勇气能量 | 勇气灯塔 | 灯塔 / 小旗 | 红橙 |
| 激浊扬清 | 整洁能量 / 守护能量 | 清洁贝壳湾 | 贝壳 / 水滴 | 青绿 |
| 开拓创新 | 创想能量 | 创想工坊 | 星星 / 灯泡 | 紫粉 / 彩虹 |
| 尊矩守法 | 规则能量 | 规则码头 | 小盾牌 / 路标 | 海蓝 |

儿童端结果示例：

```text
友爱 +20
```

老师端对应信息：

```text
维度：积极阳光
建议：+20 XP
```

## 6. 老师确认策略

### 6.1 推荐策略

采用“高置信度正向行为现场通过，低置信度或敏感内容老师确认”的分级策略。

### 6.2 高置信度正向行为

例如：

```text
我今天主动帮同学收玩具
```

流程：

- AI 判断为积极阳光。
- 建议 +20。
- 老师一键通过，或按设置自动通过。
- 儿童端显示友爱能量反馈。

### 6.3 低置信度行为

例如：

```text
我玩了积木
```

流程：

- AI 不确定。
- 老师确认卡展开。
- 老师选择维度、分值或让孩子重说。

儿童端只显示温和状态，不显示失败。

### 6.4 负向或敏感内容

例如：

```text
我今天推了别人
```

流程：

- 不在儿童主画面公开负向判断。
- 进入老师处理。
- 如需教育引导，由老师现场处理。
- 不自动扣分。

儿童端可显示：

```text
请老师帮忙
```

或只显示精灵等待动画。

## 7. 信息架构调整建议

### 7.1 主屏优先级

P0：海岛 + 精灵 + 成长树

P1：点选精灵后出现麦克风交互

P2：成长能量动画反馈

P3：老师确认角落卡

P4：今日成长数、待确认数

P5：成长档案和老师管理入口

### 7.2 不应作为主屏主线的内容

以下内容可以存在，但不应抢主屏：

- 数学竞技场
- 积分抽奖
- 积分商店
- 排行榜
- 复杂数据管理
- 大量模块入口
- 传统后台表格

这些应归入老师管理、扩展活动或二级入口。

## 8. 后续实施优先级

### P0：海岛内自助说话主流程

目标：孩子不离开海岛即可完成点精灵、说话、获得能量。

要点：

- 点击精灵聚焦。
- 麦克风图标挂在精灵附近。
- 录音、识别、成功都用动画表达。
- 结束后回到全岛。

### P1：儿童端无文字动画状态

目标：主屏整洁，幼儿不需要读说明。

要点：

- 可说话、录音中、识别中均用图标和动效。
- 不显示常驻引导文案。
- 对话文字只通过精灵气泡短暂出现。

### P2：老师角落确认卡

目标：老师能把关，但不破坏海岛体验。

要点：

- 默认紧凑。
- 显示 AI 建议和操作按钮。
- 可展开完整识别文本。
- 支持通过、修改、稍后。

### P3：德育能量视觉体系

目标：专业德育维度转化为儿童可感知的能量反馈。

要点：

- 每个维度有能量名、颜色、图标和地图区域。
- 儿童端显示能量，老师端显示专业维度。

### P4：成长反馈与档案沉淀

目标：孩子现场有成就感，老师课后有记录。

要点：

- 精灵 XP 增长。
- 成长树发光。
- 德育区域点亮。
- 完整文本和分类进入成长档案。

## 9. 验收标准

1. 幼儿能在全岛上直接点自己的精灵开始体验。
2. 体验过程中不需要进入单独的精灵选择页、录音页或结果页。
3. 主屏没有大段引导文字。
4. 录音和识别过程主要依赖动画、图标和光效。
5. 儿童端只显示短暂精灵气泡，例如“友爱 +20”。
6. 老师端能看到完整识别文本、AI 建议、分值和置信度。
7. 老师可以通过、修改或稍后复核。
8. 加分后精灵、成长树和对应德育区域有即时反馈。
9. 完成后镜头回到全岛，下一位孩子可继续点自己的精灵。
10. 数学、抽奖、商店、排行榜等扩展功能不抢占主屏主线。

## 10. 最终方向

北海成长岛后续 UI 和交互应围绕以下方向收敛：

> 海岛主画面无引导文字；孩子通过点击自己的精灵触发麦克风动画；录音和识别全程以精灵动作、声波和光效表达；识别结果只用精灵气泡短暂显示“友爱 +20”这类儿童可懂信息；完整识别文本和 AI 判断放在老师角落确认卡中。
